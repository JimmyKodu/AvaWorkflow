## 简介

AvaWorkflow 提供了一个直观的可视化界面，用于创建、编辑和执行工作流。它支持 Windows、macOS 和 Linux 系统。

### 主要特性

- ✨ 跨平台支持
- 🎨 拖拽式可视化设计
- 🔧 可扩展的活动库
- 📊 实时执行监控
- 💾 工作流持久化存储
- 🏗️ MVVM 架构设计

## 安装

### 系统要求

- .NET 8.0 SDK 或更高版本
- 支持的操作系统：Windows 10+、macOS 10.15+、Linux (主流发行版)

### 从源码构建

```bash
# 克隆仓库
git clone https://github.com/JimmyKodu/AvaWorkflow.git
cd AvaWorkflow

# 恢复依赖
dotnet restore

# 构建项目
dotnet build

# 运行应用
dotnet run --project AvaWorkflow
```

## 创建第一个工作流

### 步骤 1: 新建工作流

1. 启动 AvaWorkflow 应用
2. 点击 **文件** → **新建工作流**（或按 `Ctrl+N`）
3. 输入工作流名称
4. 选择模板或空白工作流
5. 点击 **创建**

![创建新工作流](images/step1-create-workflow.png)

**提示**：工作流名称应该简洁明了，便于识别用途。

### 步骤 2: 添加活动

左侧的**活动工具箱**包含所有可用的活动。添加活动的方法：

1. 在工具箱中浏览可用活动
2. 将活动从工具箱拖到画布上
3. 放置在合适的位置

![添加工作流活动](images/step2-add-activities.png)

**常用活动**：

| 活动类型 | 说明 | 用途 |
|---------|------|------|
| 开始活动 | 工作流入口点 | 必须有且仅有一个 |
| 决策活动 | 条件分支 | 根据条件选择执行路径 |
| 循环活动 | 重复执行 | 遍历集合或重复操作 |
| 自定义动作 | 执行自定义代码 | 实现特定业务逻辑 |
| 结束活动 | 工作流终点 | 可以有多个 |

### 步骤 3: 连接活动

通过连接活动来定义执行流程：

1. 点击活动的**输出连接点**（右侧圆圈）
2. 拖动鼠标到另一个活动的**输入连接点**（左侧圆圈）
3. 释放鼠标完成连接

![连接活动](images/step3-connect-activities.png)

**连接技巧**：
- 按住 Shift 键拖动可创建直线连接
- 点击连接线可选中它（变为蓝色）
- 按 Delete 键删除选中的连接
- 连接线上的箭头表示数据流向

### 步骤 4: 配置活动属性

为每个活动配置相应的属性：

1. 点击活动使其被选中
2. 右侧的**属性面板**会显示该活动的配置项
3. 根据需要配置各项属性

![配置活动属性](images/step4-configure-properties.png)

**常见属性**：

- **名称**：活动的唯一标识符
- **超时时间**：最大执行时间
- **重试次数**：失败后的重试次数
- **输入/输出**：数据绑定和表达式

**变量语法**：
- 使用 `${变量名}` 引用变量
- 变量可以在活动之间传递数据
- 支持表达式计算动态值

### 步骤 5: 运行和监控工作流

执行并监控您的工作流：

1. 点击工具栏的**运行**按钮（▶️）或按 F5
2. **执行监控器**显示实时状态
3. 观察每个活动的执行情况

![运行和监控工作流](images/step5-run-workflow.png)

**状态指示器**：

| 图标 | 颜色 | 状态 | 说明 |
|-----|------|------|------|
| ✓ | 绿色 | 已完成 | 活动成功执行完毕 |
| ⟳ | 黄色 | 运行中 | 活动正在执行 |
| ○ | 灰色 | 待执行 | 活动等待执行 |
| ✗ | 红色 | 失败 | 活动遇到错误 |

**其他功能**：
- **暂停**（⏸️）：临时停止执行
- **停止**（⏹️）：终止工作流
- **单步执行**：逐个活动执行，便于调试
- **查看日志**：访问详细的执行日志

## 常用功能

### 变量和表达式

#### 变量定义

工作流中的变量用于存储和传递数据：

```javascript
// 简单变量引用
${用户名}
${年龄}

// 对象属性访问
${用户.姓名}
${订单.总金额}

// 数组访问
${列表[0]}
${数据[索引]}

// 算术运算
${数量 + 1}
${价格 * 数量}

// 比较运算
${年龄 >= 18}
${状态 == "激活"}

// 逻辑运算
${有效 && 激活}
${条件1 || 条件2}
```

### 错误处理

#### 重试配置

为活动配置自动重试：
- **重试次数**：尝试次数
- **重试延迟**：重试间隔时间
- **指数退避**：每次重试增加延迟时间

#### 错误处理策略

1. **Try-Catch 模式**：使用决策活动检查错误
2. **补偿机制**：定义活动来撤销之前的工作
3. **死信队列**：将失败的项目路由到单独的队列

### 并行执行

同时运行多个活动：

1. 从单个活动创建多个输出连接
2. 不同路径上的活动并行执行
3. 使用**合并活动**同步完成

### 调试模式

启用调试模式获取详细执行信息：

1. 点击 **查看** → **调试模式**
2. 在活动上设置断点
3. 逐步执行，一次执行一个活动
4. 在每个步骤检查变量值

## 最佳实践

### 设计原则

1. **保持简单**：将复杂工作流拆分为更小、可管理的部分
2. **组件重用**：为常见模式创建可重用的子工作流
3. **错误处理**：始终计划失败场景
4. **文档说明**：使用描述性名称并添加注释

### 性能优化

1. **避免深度嵌套**：限制嵌套循环和决策的深度
2. **使用并行执行**：对独立活动使用并行执行
3. **优化数据访问**：最小化文件 I/O 和网络调用
4. **设置超时**：始终设置适当的超时值

### 安全考虑

1. **验证输入**：始终验证来自外部源的数据
2. **保护凭据**：使用安全存储来保存密码和 API 密钥
3. **访问控制**：实施适当的授权机制
4. **审计日志**：跟踪工作流执行以符合合规要求

## 常见问题

### 工作流无法启动

**症状**：运行按钮被禁用或点击后无反应

**解决方案**：
1. 检查验证错误（红色显示）
2. 确保工作流有开始活动
3. 验证所有必需属性已配置
4. 检查是否有未连接的活动

### 活动超时

**症状**：活动显示超时错误

**解决方案**：
1. 增加超时值
2. 优化活动逻辑
3. 检查网络问题（对于 I/O 活动）
4. 查看重试配置

### 找不到变量

**症状**：表达式错误：变量未定义

**解决方案**：
1. 检查变量名拼写
2. 验证变量在使用前已设置
3. 检查变量作用域
4. 在首次使用前初始化变量

## 架构概览

AvaWorkflow 采用模块化分层架构：

![架构图](images/architecture.png)

### 核心组件

1. **UI 层（Avalonia）**
   - 可视化工作流设计器
   - 属性编辑器
   - 执行监控器
   - 基于 MVVM 模式构建

2. **工作流引擎（核心逻辑）**
   - 工作流执行
   - 活动调度
   - 状态管理
   - 错误处理和重试逻辑

3. **活动库（扩展）**
   - 内置活动
   - 自定义活动支持
   - 活动元数据和验证

4. **存储（持久化）**
   - 工作流序列化/反序列化
   - 支持多种格式（JSON、XML）
   - 版本控制友好
